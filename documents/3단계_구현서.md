# 3단계 구현서: Windows DNS 캐시 TTL과 hosts 파일 확인

## 1. 단계 결과

3단계는 완료했다.

이 단계에서는 Windows의 일반 이름 조회 결과가 Windows DNS 캐시와 `hosts` 파일의 영향을 받는지 확인했다. DNS 캐시를 직접 구현하거나 `hosts` 파일을 프로그램으로 수정하지 않았다.

## 2. 구현 내용

`dns_trace.py`에 아래 함수를 추가했다.

```python
def resolve_domain_ipv4_with_windows(domain: str) -> list[str]:
```

이 함수는 Python 표준 라이브러리 `socket.getaddrinfo()`로 Windows에 도메인 이름 조회를 맡긴다.

- IPv4(`AF_INET`) 결과만 반환한다.
- 같은 IP가 여러 번 반환되면 한 번만 남긴다.
- 마지막 점(`.`)이 붙은 도메인은 일반 조회 전에 제거한다.

`main.py`는 직접 DNS 추적과 Windows 일반 조회를 모두 실행한다.

```python
trace = dns_trace.trace_domain(domain, root_sever_ip)
dns_trace.print_trace(domain, trace)

system_ips = dns_trace.resolve_domain_ipv4_with_windows(domain)
print(f"윈도우에서 조회한 도메인 IP: {system_ips}")
```

## 3. 확인한 내용

### 3.1 Windows 일반 조회

`www.example.com.`을 Windows 일반 조회 함수로 조회했다. `hosts` 파일에 별도 설정이 없을 때, 직접 DNS 추적으로 얻은 IPv4와 같은 결과가 반환되는 것을 확인했다.

Windows 일반 조회는 아래 순서로 동작한다.

```text
Windows DNS 캐시 확인
→ hosts 파일 설정 확인
→ 둘 다 없을 때 Windows에 설정된 DNS 서버에 질의
```

반면 DNS Tracer의 직접 추적은 루트 DNS 서버부터 직접 질의하므로 Windows DNS 캐시와 `hosts` 파일을 사용하지 않는다.

### 3.2 DNS 캐시 TTL 확인

아래 명령으로 Windows DNS 캐시를 확인하고 초기화했다.

```powershell
ipconfig /displaydns
ipconfig /flushdns
```

확인 순서는 다음과 같다.

1. `ipconfig /flushdns`로 기존 캐시를 비운다.
2. `resolve_domain_ipv4_with_windows()`로 `www.example.com`을 조회한다.
3. `ipconfig /displaydns`에서 `www.example.com`의 A 레코드와 남은 TTL을 확인한다.
4. 잠시 뒤 다시 확인해 TTL 값이 줄어드는 것을 확인한다.

이를 통해 Windows는 DNS 서버에서 받은 IPv4 결과를 캐시에 보관하고, TTL이 남아 있는 동안 그 결과를 재사용한다는 점을 확인했다.

### 3.3 hosts 파일 적용 확인

Windows `hosts` 파일의 위치는 아래와 같다.

```text
C:\Windows\System32\drivers\etc\hosts
```

실습을 위해 아래 설정을 임시로 추가했다.

```text
127.0.0.1  www.example.com
```

그 뒤 `ipconfig /flushdns`를 실행하고 결과를 확인했다.

- `ipconfig /displaydns`에 `www.example.com → 127.0.0.1` 항목이 나타났다.
- Windows 일반 조회는 `127.0.0.1`을 반환했다.
- 직접 DNS 추적은 `hosts` 파일과 무관하게 실제 DNS 서버가 반환한 IPv4를 반환했다.

Windows는 `hosts` 파일의 도메인-IP 설정을 로컬 리졸버 캐시에 반영할 수 있다. 따라서 일반 조회를 실행하기 전에도 `ipconfig /displaydns`에서 해당 항목이 보일 수 있다.

실습 후에는 `hosts` 파일에 추가한 한 줄을 삭제하고 `ipconfig /flushdns`를 실행해 원래 상태로 복원한다.

## 4. 이 단계에서 얻은 결론

```text
직접 DNS 추적
→ 실제 DNS 서버가 알려 주는 IPv4를 확인

Windows 일반 조회
→ Windows DNS 캐시와 hosts 파일을 반영한 IPv4를 확인
```

- DNS 캐시는 이전 조회 결과를 TTL 동안 재사용한다.
- `hosts` 파일은 Windows 일반 조회에서 DNS 서버 질의보다 먼저 적용되는 로컬 도메인-IP 설정이다.
- 직접 DNS 추적은 Windows의 캐시와 `hosts` 파일의 영향을 받지 않는다.

## 5. 제외한 범위

- DNS 캐시를 직접 구현하거나 저장 구조를 분석하는 작업
- 프로그램이 `hosts` 파일을 자동으로 수정하는 작업
- AAAA, CNAME 등 A 레코드 이외의 조회
- 직접 DNS 추적 응답의 TTL을 Windows 캐시 TTL과 비교하는 작업
- 오류 처리와 별도 문서화 단계

3단계까지의 범위로 DNS Tracer 프로젝트를 마무리한다.
