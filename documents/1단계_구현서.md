# 1단계 구현서: 루트 DNS 서버에 직접 질의하기

## 1. 목표

이 단계에서 만드는 프로그램은 사용자가 입력한 도메인에 대해 **루트 DNS 서버에 직접 DNS 질의를 보내고**, 그 응답에 들어 있는 TLD(최상위 도메인) 네임서버 정보를 보여 주는 CLI 도구다.

예를 들어 `www.example.com`을 입력하면 루트 서버는 최종 IP 주소를 알려 주지 않는다. 대신 `.com`을 담당하는 TLD 네임서버 목록을 알려 준다. 이 위임 정보를 확인하는 것이 1단계의 완료 목표다.

```text
www.example.com 입력
→ 루트 DNS 서버에 직접 질의
→ .com TLD 네임서버(NS) 목록 확인
→ 네임서버의 IP 주소(glue record)가 있으면 함께 출력
```

이 문서는 완성된 전체 코드를 제공하지 않는다. 실제 구현 때 필요한 코드 조각과, 각 조각이 하는 일을 설명한다.

## 2. 이번 단계의 범위

포함하는 일은 다음과 같다.

- 명령줄에서 도메인 하나를 입력받는다.
- IANA root hints를 바탕으로 준비한 루트 서버 주소 중 하나에 질의한다.
- 재귀 요청을 사용하지 않고 DNS 질의를 보낸다.
- 응답의 `Authority` 섹션에서 TLD 네임서버(NS) 정보를 찾는다.
- 응답의 `Additional` 섹션에 있는 glue A/AAAA 레코드를 출력한다.
- 시간 초과 시 다른 루트 서버에 다시 시도한다.

아직 하지 않는 일은 다음과 같다.

- TLD 서버 또는 권한 DNS 서버에 이어서 질의하기
- 최종 A 레코드와 IP 주소 찾기
- CNAME, AAAA, TTL 비교, 캐시 관찰
- 시스템 기본 DNS 조회와 결과 비교

## 3. 기술 선택

언어는 Python을 사용한다. 이 프로그램은 서버를 만들거나 API를 제공하지 않는 CLI 클라이언트이므로 웹 프레임워크는 필요 없다.

DNS 패킷을 직접 조립하고 해석하는 대신 `dnspython` 라이브러리를 사용한다. 이 라이브러리는 DNS 메시지 생성, UDP 전송, NS/A/AAAA 레코드 해석을 제공한다.

```text
Python 3.11 이상
dnspython
```

개발 환경에서는 아래처럼 설치한다.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install dnspython
```

`requirements.txt`에는 다음 한 줄을 기록한다.

```text
dnspython
```

## 4. DNS 질의에서 알아야 할 내용

DNS 응답은 크게 `Answer`, `Authority`, `Additional` 섹션으로 나뉜다.

루트 서버에 `www.example.com`의 A 레코드를 물으면, 보통 `Answer`는 비어 있다. 이는 실패가 아니다. 루트 서버는 `example.com`의 IP를 직접 관리하지 않기 때문이다.

대신 응답은 다음 정보를 담는다.

```text
Authority: .com을 담당하는 NS 레코드
Additional: 그 NS 서버에 바로 접속할 수 있는 A/AAAA 주소(glue record)
```

여기서 얻은 TLD 네임서버가 2단계의 질의 대상이 된다.

### 재귀 요청을 끄는 이유

일반 DNS 조회는 보통 로컬 또는 공용 재귀 리졸버에게 "최종 답을 찾아 달라"고 요청한다. 이 프로젝트에서는 루트 → TLD → 권한 서버를 직접 따라가며 배워야 하므로 재귀 요청 비트(RD)를 끈다.

```text
RD=0: 루트 서버가 아는 다음 단계의 위임 정보만 받는다.
RD=1: 재귀 리졸버에게 최종 답을 대신 찾아 달라고 요청한다.
```

처음에는 모든 내용을 `main.py` 한 파일에 작성해도 된다. 동작을 이해한 뒤 아래처럼 나누면 역할이 분명해진다.

├─ main.py             # CLI 입력, 전체 흐름, 출력 호출
├─ root_hints.py       # 루트 서버 이름과 IP 목록

`root_query.py`는 화면에 바로 출력하지 않고 결과를 데이터로 돌려주는 편이 좋다. 그러면 2단계에서 같은 결과를 이어 받아 다음 서버에 질의할 수 있고, 테스트도 쉬워진다.

## 6. 중요한 코드 조각

### 6.1 루트 서버 목록

루트 서버의 이름과 IPv4 주소를 준비한다. 실제 목록은 IANA root hints에서 가져오며, 가져온 날짜와 출처를 주석 또는 문서에 남긴다. 프로그램 실행 때마다 인터넷에서 내려받을 필요는 없다.

```python
ROOT_SERVERS = [
    {"name": "a.root-servers.net.", "ipv4": "198.41.0.4"},
    # IANA root hints의 다른 루트 서버도 추가한다.
]
```

1단계에서는 IPv4 주소만으로 시작해도 충분하다. 서버 한 곳이 응답하지 않을 수 있으므로 실제 구현에는 여러 주소를 넣는다.

### 6.2 입력 도메인 정리

DNS 질의에는 절대 도메인 이름을 사용한다. 마지막 점(`.`)은 루트 기준의 완전한 이름임을 나타낸다.

```python
domain = raw_domain.strip().lower().rstrip(".") + "."
```

예를 들어 `Example.COM`, `example.com`, `example.com.`은 모두 `example.com.`으로 정리한다. 빈 문자열이면 질의를 보내지 않고 입력 오류를 보여 준다. 첫 구현에서는 일반적인 ASCII 도메인만 지원하고, 한글 도메인(IDN)은 이후 확장 항목으로 남겨도 된다.

### 6.3 DNS 메시지 생성

`dnspython`의 `make_query()`로 "이 도메인의 A 레코드를 알려 달라"는 메시지를 만든다.

```python
import dns.message
import dns.rdatatype

query = dns.message.make_query(
    domain,
    dns.rdatatype.A,
    want_recursion=False,
)
```

`dns.rdatatype.A`는 IPv4 레코드 질의를 뜻한다. 이번 단계는 최종 IPv4를 받는 것이 목적은 아니지만, 다음 단계까지 그대로 이어 갈 대표 질의 종류로 A를 사용한다. `want_recursion=False`가 RD=0 설정이다.

### 6.4 특정 루트 서버로 UDP 질의 보내기

```python
import dns.query

response = dns.query.udp(
    query,
    where=root_server_ip,
    timeout=3,
)
```

`where`에는 시스템 DNS 주소가 아니라 root hints에서 선택한 루트 서버의 IP를 넣는다. 이 코드가 "직접 질의"를 만드는 부분이다. DNS의 기본 전송 방식은 UDP와 53번 포트이며, `dnspython`이 포트 지정과 패킷 송수신을 처리한다.

응답 대기가 끝나면 예외가 발생할 수 있으므로, 시간 초과나 네트워크 오류가 나면 다음 루트 서버를 시도한다.

```python
for root_server in ROOT_SERVERS:
    try:
        response = dns.query.udp(query, root_server["ipv4"], timeout=3)
        break
    except (dns.exception.Timeout, OSError):
        continue
else:
    raise RuntimeError("응답한 루트 DNS 서버가 없습니다.")
```

위 코드는 재시도의 개념을 보여 주기 위한 조각이다. 실제 코드에서는 마지막 오류 원인과 시도한 서버 목록도 결과에 남긴다.

### 6.5 응답 코드 확인

질의가 도착했다고 해서 항상 정상 결과인 것은 아니다. 응답 코드를 먼저 읽는다.

```python
import dns.rcode

rcode_text = dns.rcode.to_text(response.rcode())
if rcode_text != "NOERROR":
    # SERVFAIL, NXDOMAIN 등의 상태를 출력하고 종료한다.
    pass
```

일반적인 TLD 위임 응답은 `NOERROR`다. 단, `NOERROR`이면서 `Answer`가 비어 있는 것은 루트 서버 질의에서는 정상일 수 있다.

### 6.6 Authority에서 TLD 네임서버 찾기

```python
import dns.rdatatype

ns_records = []

for rrset in response.authority:
    if rrset.rdtype == dns.rdatatype.NS:
        for rdata in rrset:
            ns_records.append({
                "zone": rrset.name.to_text(),
                "hostname": rdata.target.to_text(),
            })
```

예상되는 결과는 다음과 비슷하다.

```text
zone: com.
hostname: a.gtld-servers.net.
hostname: b.gtld-servers.net.
```

`zone`은 위임된 TLD이고, `hostname`은 다음 단계에서 질의할 DNS 서버의 이름이다.

### 6.7 Additional에서 glue record 찾기

네임서버 이름만 받으면 그 이름의 IP를 다시 찾아야 한다. 루트 서버는 보통 다음 질의를 바로 할 수 있도록 네임서버 IP도 함께 주는데, 이것이 glue record다.

```python
glue_records = {}

for rrset in response.additional:
    if rrset.rdtype in (dns.rdatatype.A, dns.rdatatype.AAAA):
        hostname = rrset.name.to_text()
        glue_records[hostname] = [rdata.address for rdata in rrset]
```

출력할 때는 `ns_records`의 `hostname`에 맞는 IP를 `glue_records`에서 찾아 함께 보여 준다. glue record가 없을 수도 있으므로, 없는 경우에는 오류로 처리하지 않고 "제공되지 않음"으로 표시한다. IP를 별도로 해결하는 일은 2단계 이후에 다룬다.

## 7. 함수의 입출력 형태

루트 질의 함수는 출력 문자열 대신 아래와 같은 결과를 반환하는 형태가 좋다.

```python
{
    "domain": "www.example.com.",
    "query_type": "A",
    "root_server": {
        "name": "a.root-servers.net.",
        "ipv4": "198.41.0.4",
    },
    "rcode": "NOERROR",
    "delegated_zone": "com.",
    "nameservers": [
        {
            "hostname": "a.gtld-servers.net.",
            "addresses": ["192.5.6.30"],
        },
    ],
}
```

이 자료 구조는 1단계의 출력에도 쓰이고, 2단계에서는 `nameservers`의 주소를 TLD 질의 대상으로 넘기는 데도 쓰인다. 실제 응답 전문이 필요할 때는 별도 `raw_response` 필드에 저장하거나 `--verbose` 옵션에서만 출력한다.

## 8. CLI 동작과 출력 예시

실행 형태는 단순하게 유지한다.

```text
python main.py www.example.com
```

출력에는 학습에 필요한 정보만 순서대로 담는다.

```text
입력 도메인: www.example.com.
질의 서버: a.root-servers.net. (198.41.0.4)
질의 내용: www.example.com. IN A
재귀 요청: 사용 안 함 (RD=0)

응답 상태: NOERROR
응답 종류: TLD 위임
위임된 영역: com.
TLD 네임서버:
- a.gtld-servers.net. (192.5.6.30)
- b.gtld-servers.net. (192.33.14.30)

다음 단계: 위 서버 중 하나에 www.example.com. IN A 질의를 보낸다.
```

서버 목록과 IP는 질의 시점의 실제 응답에 따라 달라진다.

## 9. 오류 처리 기준

1단계에는 아래 정도의 오류 처리가 있으면 충분하다.

| 상황 | 처리 방식 |
| --- | --- |
| 도메인 입력이 비어 있음 | 사용법을 출력하고 종료한다. |
| 루트 서버 한 곳 시간 초과 | 다음 루트 서버로 재시도한다. |
| 모든 루트 서버가 실패 | 시도한 서버와 마지막 오류를 출력한다. |
| `NOERROR`이 아닌 응답 코드 | 코드 이름을 출력하고 다음 단계로 진행하지 않는다. |
| NS 레코드가 없음 | 받은 응답 전문을 확인할 수 있게 하고 비정상 응답으로 처리한다. |
| glue record가 없음 | NS 이름은 출력하고 IP는 "제공되지 않음"으로 표시한다. |

## 10. 완료 확인 방법

다음 도메인을 직접 실행해 본다.

```text
example.com
google.com
naver.com
```

각 실행에서 아래 조건을 확인하면 1단계는 완료다.

- 루트 서버의 IP로 직접 UDP 질의를 보냈다.
- 재귀 요청이 꺼져 있다.
- 응답 코드가 표시된다.
- 입력 도메인의 TLD에 해당하는 NS 레코드가 출력된다.
- glue A 또는 AAAA 레코드가 있으면 함께 출력된다.
- 프로그램이 최종 IP 조회를 시도하지 않고 다음 TLD 질의 대상을 안내한다.

## 11. 2단계로 넘길 정보

2단계를 시작할 때 1단계 결과 중 아래 값만 넘기면 된다.

```text
입력 도메인
질의 레코드 종류(A)
TLD 네임서버 이름
TLD 네임서버의 glue IP 주소
```

따라서 1단계의 책임은 "루트 응답을 받아 다음 DNS 서버를 정확히 찾는 것"으로 끝난다.
