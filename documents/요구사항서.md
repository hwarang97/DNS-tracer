# DNS 이름 풀이 추적기 요구사항서

## 1. 프로젝트 목표

사용자가 입력한 도메인이 최종 IP 주소를 얻기까지의 DNS 조회 경로를 확인할 수 있는 학습용 진단 도구를 만든다.

도구는 루트 DNS 서버, 최상위 도메인(TLD) DNS 서버, 권한 DNS 서버에 차례로 질의하고 그 경로와 최종 IP 주소를 보여 준다. 이를 통해 도메인 이름이 IP 주소로 조회되는 과정을 이해하는 것이 목표다.

## 2. 핵심 원칙

- 이 프로젝트는 DNS 서버나 재귀 DNS 리졸버를 새로 구현하지 않는다.
- 기존에 운영 중인 DNS 서버에 직접 질의하는 클라이언트 도구를 만든다.
- 일반 DNS 조회와 직접 추적 조회를 구분해 보여 준다.
- 처음에는 명령줄(CLI) 도구로 만들고, 화면 구성은 우선순위에 두지 않는다.

## 3. 기능 요구사항

### 3.1 직접 추적 조회

- 사용자가 도메인을 입력할 수 있어야 한다.
- IANA의 root hints 정보를 이용해 루트 DNS 서버에 질의할 수 있어야 한다.
- 루트 DNS 서버의 응답에서 TLD DNS 서버 정보를 확인해야 한다.
- TLD DNS 서버의 응답에서 권한 DNS 서버 정보를 확인해야 한다.
- 권한 DNS 서버에서 A 레코드를 조회해 IPv4 주소를 출력해야 한다.
- 각 단계에서 질의 대상 서버와 다음 질의 대상을 출력해야 한다.

### 3.2 레코드와 결과 표시

- A 레코드(IPv4) 조회 결과를 표시해야 한다.
- 최종 IP 주소가 여러 개인 경우 모두 표시한다.

### 3.3 일반 조회 비교

- 시스템 기본 DNS 리졸버를 사용하는 일반 조회 결과를 확인할 수 있어야 한다.
- 일반 조회 결과와 직접 추적 조회 결과를 비교할 수 있어야 한다.

### 3.4 확장 실습

- Windows DNS 캐시의 TTL을 확인한다.
- 반복 조회를 통해 캐시와 TTL의 관계를 관찰한다.
- `hosts` 파일을 적용한 일반 조회 결과를 비교할 수 있도록 안내한다.

## 4. 완료 기준

도메인 하나를 입력했을 때 아래 흐름을 결과 화면에서 확인할 수 있으면 핵심 목표를 달성한 것으로 본다.

```text
입력 도메인
→ 루트 DNS 서버
→ TLD DNS 서버
→ 권한 DNS 서버
→ A 레코드
→ 최종 IP 주소
```

## 5. 범위 밖 항목

- 재귀 DNS 리졸버 서버 구현
- 권한 DNS 서버 구현 및 도메인 Zone 운영
- DNSSEC, DoH, DoT의 상세 구현
- 웹 브라우저 또는 웹사이트 접속 기능 구현
